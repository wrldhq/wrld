## 5. Mobile regression reasoning

No device/emulator rendering is available here, so this is structural reasoning, same basis as V20.1's mobile summary:

- The hero fix is a single pseudo-element with a fixed 8px height and no width/breakpoint dependency — cannot affect any layout at any viewport size.
- `.section-head.center` only sets `text-align:center`, an existing, already-mobile-tested class used elsewhere on these same pages (e.g. `programs.html`'s own page-header section already uses `.container.text-center`).
- `.grid-recommend` was deliberately built to be responsive without a separate breakpoint: `flex-wrap:wrap` plus a `260px` flex-basis means only one card fits per line under roughly 380–400px of available width, which is exactly the single-column stack the rest of the site already uses on mobile — verified by reading the existing mobile breakpoints for `.pb-grid`/`.programs-grid` (`grid-template-columns:1fr !important` under ~480px) and confirming `.grid-recommend` reaches the same one-per-row end state through different, breakpoint-free CSS.
- `.btn-icon`'s fix only adds flex centering and `line-height:1` — same 44×44px box as before, no size or position change relative to surrounding layout.
- The mentor-deletion changes are entirely inside Owner/Administrator dashboard JavaScript and a server-side Edge Function — no markup or CSS affecting any mobile layout was touched.

Manual confirmation at 320/360/375/390/414/430/768/820px and desktop widths, across real iPhone Safari and Android Chrome, is still recommended before shipping, since this environment cannot render either — same caveat as V20.1.
