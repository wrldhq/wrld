## 1. Root cause: Dashboard shows "Take the Assessment" for completed users

**This was not a synchronization/timing bug.** `getState().assessment` was already correct and already present the whole time — proven by the fact that clicking the button opened the already-completed Passport immediately, with no re-take. The real bug was a **missing fallback in one specific calculation**, in `dashboard.html`'s "Your Learning Path" card:

```js
const recommendedPathKey = (s.assessment && weakestKey) ? SECTION_RECS[weakestKey].path : null;
```

`SECTION_RECS` (in `data.js`) intentionally has `path: null` for one section — **Community & Purpose** — because no single Learning Path maps to it. If a learner's *weakest* section happens to be that one, `SECTION_RECS[weakestKey].path` is `null`, `path` ends up `null`, and the card fell all the way through to its "you haven't taken the assessment yet" empty state — even though `s.assessment` was completely real and correct.

`assessment.html`'s own results page already solved this exact problem for its own "Suggested Learning Path" card, by falling back through every section from weakest to strongest until it finds one with a real path. `dashboard.html` never had that same fallback. The fix mirrors it exactly:

```js
let recommendedPathKey = null;
if(s.assessment && s.assessment.sectionScores){
  const scores = s.assessment.sectionScores;
  const rankedWeakToStrong = Object.keys(scores).sort((a,b)=>scores[a]-scores[b]);
  recommendedPathKey = rankedWeakToStrong.map(k=>SECTION_RECS[k] && SECTION_RECS[k].path).find(Boolean) || null;
}
```

Nothing was hardcoded — this reads the same real, already-synced `s.assessment.sectionScores` and just tries every section instead of only the single weakest one. A learner who has genuinely never taken the assessment (`s.assessment` is `null`) still, correctly, sees the "Take the Assessment" prompt.

## 2. Root cause: blank "Helpful Resources" and "Suggested Live Learning" sections

**Confirmed root cause: a missing `initReveal()` call — not empty data, not a rendering failure, not mobile-only CSS.**

Every card across the site fades in via the shared `.reveal` CSS class (`opacity:0` until `app.js`'s `initReveal()` observes it and adds `.in`). `initPage()` calls `initReveal()` exactly **once**, early, right after the page loads — long before a learner finishes the Assessment. The *static* headings ("📥 Helpful Resources", "🎥 Suggested Live Learning") already exist in the page's HTML at that first sweep (just hidden behind the results view's own `.hidden` class), so they get observed correctly and reveal fine once shown. But the individual **cards** inside those sections are built later, dynamically, via `innerHTML`, when the learner actually finishes the assessment — they didn't exist yet at that one-time sweep, so they were never observed at all, and stayed at `opacity:0` forever. Visually, that's exactly "the heading shows, a large blank area follows" — the cards are there in the DOM, correctly computed, just permanently invisible.

Every other page on the site that injects `.reveal` content after its own initial load already re-calls `initReveal()` afterward — `dashboard.html`, `events.html`, `community.html`, `playbook.html`, `program.html`, `owner-dashboard.html`, and more all do this. `assessment.html` was the **one page in the entire codebase** missing that same, already-established call. The fix is one line, at the end of `renderPassport()` (the single function both a fresh completion and a returning/already-completed visit both funnel through):

```js
setTimeout(initReveal, 30);
```

This also explains the desktop-vs-mobile framing in this bug report: this defect is not actually device-specific (there is no screen-width media query involved) — but a device or browser with "Reduce Motion" turned on (common in accessibility settings, and common on a desktop dev/test machine) has a separate rule, `@media(prefers-reduced-motion:reduce){ .reveal{opacity:1;} }`, that forces every `.reveal` element permanently visible regardless of whether it was ever observed — which would make the exact same underlying bug invisible on a "Reduce Motion" desktop while still fully broken on an ordinary phone. The fix resolves it everywhere, regardless of that setting.

## 4. Root cause: Dashboard mobile scale / horizontal overflow

**Confirmed exact element.** The viewport meta tag is correct and identical across every page (`width=device-width, initial-scale=1.0`, one copy, no duplicates) — this was not a viewport-tag problem. The actual cause: `.btn` is `white-space:nowrap` site-wide by design (so short labels like "Start Now →" never break awkwardly), but `dashboard.html`'s "Your Learning Path" card builds a button with genuinely dynamic, sometimes long text:

```html
<a ... class="btn btn-primary btn-sm">Continue: ${nextStep.title} →</a>
```

For a long Playbook title (e.g. "Continue: Build Your First Resume (Even With No Experience) →"), that button has no width cap and cannot wrap, so it renders at its full intrinsic width — wider than a phone screen. That pushes the whole page's real `scrollWidth` past the device width, which is what actually produced the "loads zoomed in, blank space when you zoom out" symptom (the page genuinely was wider than the viewport; it wasn't a scaling bug). The same unbounded-width pattern also existed in `events.html`'s Live-Learning-by-Program cards.

## 5 & 6. Dashboard widget compression and Live Learning card compression

Both share the same underlying anti-pattern already identified and fixed once in V25 for the Assessment's "Start Here"/"Suggested Path" cards and the Dashboard's "Your Next Step" card: an icon (fixed width) + a text column + a button, all in one flex row. Two spots still had it uncovered:

- `dashboard.html`'s "Your Learning Path" card CTA row ("View Full Path" / "Continue: {title}").
- `events.html`'s Live-Learning-by-Program cards (icon + program title/description + "View Program" button in one row) — these are the "Financial Literacy Academy / Future Leaders / Career Bootcamp" cards on the Live Learning page.

Fixed with the same, already-established pattern extended to these two spots, inside the existing `@media(max-width:720px)` block in `styles.css`: the row stacks to a single column, the icon shrinks to the same 64px already used elsewhere, and the button becomes full-width with `white-space:normal` so long text wraps instead of overflowing. Desktop (`>720px`) is completely untouched — none of these rules exist outside that one mobile breakpoint.

## 8. "Current Mentors" empty state

Two separate things were fixed:

1. **Copy and CTA.** Replaced the old "No Mentors have joined yet" text with the requested warmer copy and a real "Apply to Mentor →" button linking to `become-mentor.html` (the existing, correct mentor-application page).
2. **Root cause of the "large empty area."** `renderMentorsList()`'s no-mentors branch ended with a `return` statement that ran *before* the function's own, existing `setTimeout(initReveal, 20)` call at the very end — so this one card (`class="card reveal ..."`) never got observed and stayed invisible, exactly like items 2/3 above. The `return` now runs `setTimeout(initReveal, 20)` first.

When real, approved Mentors exist, the original card-rendering path (unchanged) already calls `initReveal()` correctly and displays them exactly as before — this fix only affects the empty-state branch.

## 9. Navigation active-state bug (About WRLD / Connect both highlighted)

**Confirmed exact cause.** In `data.js`'s `NAV_GROUPS`, the "Connect" group's "Partner With Us" item was defined with `key:'about'` — identical to every item in the separate "About WRLD" group. `renderNavDropdown()`'s active-group check (`group.items.some(it=>it.key===activeKey)`) matches on key alone, so both groups satisfied it at once whenever `about.html` (which calls `initPage('about')`) rendered the header. Fixed by giving "Partner With Us" its own key (`'partner'`) — the link itself (still `about.html#partner`) is unchanged; only the nav-highlighting key changed. Only one navigation group can ever match a given `activeKey` now.
