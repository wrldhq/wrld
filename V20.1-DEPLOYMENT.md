# WRLD Website V20.1 — Deployment Guide

WRLD is a 100%-static, no-build-step site (no bundler, no framework). "Deploying" the frontend means uploading the files as-is to static hosting. The backend (Postgres schema, RLS policies, RPC functions, Edge Functions) lives in Supabase and is **not** touched by a frontend deploy — those are separate steps below.

**Project:** `hnmpcjdlhuhetgkzgdgl` (org: WRLD-production) — Project URL: `https://hnmpcjdlhuhetgkzgdgl.supabase.co`

## 3. Deploying the frontend

Upload every file in this project (outside `supabase/`) to your static host exactly as-is — file names and relative paths must not change (scripts are loaded by exact filename with cache-busting `?v=` query strings; see each page's `<script src="...">` tags). No build step, no `npm run build`, no bundler.

If using Cloudflare Pages / Netlify / Vercel static hosting: point the project at the repository root, leave the build command empty, and set the output directory to the repository root (`.`).

**Important:** if this project is connected to GitHub, pushing/uploading to GitHub only updates the frontend once your host's deploy hook runs. **It does not apply migrations and does not deploy Edge Functions** — those live in Supabase, not in your static host, and require the separate steps below every time `supabase/migrations/` or `supabase/functions/` changes, even if the GitHub push succeeds.

## 4. Deploying migrations

Migration `20260731090000_037_v20_community_and_mentor_repair.sql` is **already applied** to the live `hnmpcjdlhuhetgkzgdgl` project — no action needed there. Use this section only if setting up a fresh/new Supabase project from this codebase.

### Option A — Supabase CLI (`supabase db push`)
```bash
supabase login
supabase link --project-ref hnmpcjdlhuhetgkzgdgl
supabase db push
```
This applies every migration under `supabase/migrations/` in filename order that isn't already recorded as applied on the target project.

### Option B — SQL Editor (manual, no CLI)
1. Open the Supabase Dashboard → your project → **SQL Editor**.
2. Open each file under `supabase/migrations/` **in filename order** (they're timestamp-prefixed, so alphabetical order is the correct order) and run its contents as a query.
3. For V20.1 specifically, the one that matters is `20260731090000_037_v20_community_and_mentor_repair.sql` — but on a brand-new project every earlier migration must be run first, since later ones depend on tables/columns/functions the earlier ones create.

Verify afterward:
```sql
select proname from pg_proc
where proname in ('delete_mentor_application','moderation_set_community_status','report_community_content');
```
All three should be returned.

## 5. Deploying Edge Functions

The `delete-user` function is **already deployed** (version 2, `ACTIVE`) on `hnmpcjdlhuhetgkzgdgl`. Use this section only for a fresh project.

### Supabase CLI
```bash
supabase login
supabase link --project-ref hnmpcjdlhuhetgkzgdgl
supabase functions deploy delete-user
supabase functions deploy mentor-application-submitted
supabase functions deploy mentor-application-status-changed
supabase functions deploy orbit-ai
```
(All four are the real function slugs present under `supabase/functions/` in this project — not placeholders.)

### Required secrets (set once per project, via CLI or Dashboard → Edge Functions → Secrets)
```bash
supabase secrets set SUPABASE_URL=https://hnmpcjdlhuhetgkzgdgl.supabase.co
supabase secrets set SUPABASE_SERVICE_ROLE_KEY=<service role key — Dashboard → Project Settings → API — never commit this>
```
`orbit-ai` additionally requires whatever LLM provider key it's configured to call (see `ORBIT-AI-SETUP.md` in this project for that function's specific secret name — it is a separate credential from the two above).

`SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are provided automatically inside the Supabase Edge Function runtime for functions deployed via the CLI/dashboard against their own project, but confirm both are present under Dashboard → Edge Functions → `delete-user` → Secrets if a manually-triggered deploy ever reports them missing.

**Reminder:** GitHub does not deploy Edge Functions. `supabase functions deploy <slug>` (or the Dashboard's function editor) is the only thing that does.
